③ Conformance 探针测试输入

探针输入预期结果
basic 公司年休假的基本规则是什么？ completed
input_required 我想请假 input-required（等补充）
resume start: 我想请年假 input-required
resume: 明天一天 same task/context 继续 → completed
cancel=false 预期：页面不显示 Stop；探针集合不含 cancel（合同 cancel: false）； 直接调 tasks/cancel 应收到 unsupported-operation 错误，且不得只是 CSS 隐藏。

④ 页面操作步骤（按序）

  1. 启动 Public A2A：设置 HR_ASSISTANT_A2A_HOST/PORT/PUBLIC_URL/AUTH_MODE 并启动进程
  2. health：GET <public_url>/health，确认 status/agent/version/protocol_version/auth_mode
  3. live AgentCard：GET <public_url>/.well-known/agent-card.json，card.url 即 JSON-RPC 端点
  4. Register Contract：粘贴上方完整版合同 → 得到 contract_snapshot_id
  5. Create Revision → Register Runtime（Endpoint / Auth）→ Conformance（填探针输入）→ Publish
  6. Route/Activation：配置 Route / ExecutionBinding 与允许的 Invocation Context
  7. Employee 会话：新建会话 → Selector 选择发布的 Agent → 发 basic query → 验证 answer
  8. input-required / resume：缺信息任务 → 追问 → 补充 → same Invocation resume → completed

⑤ 验证要点（通过标准）

项标准
Resume 证据same Invocation、same Binding、same taskId/contextId、无 continuation Invocation、无 Binding 替换
Context 正确性subject 来自 login Principal；resume 用 same subject；current_datetime 每次 fresh；internal ID 不外发
UI 错误Provider 失败时员工看到稳定错误，不显示 raw JSON-RPC stack / bearer / 内部 endpoint 诊断
跨端一致性Web start → A2A contextId → Desktop 同 Thread → 新 Turn 复用 contextId；新 Invocation taskId 必须不同
无自证报告本包只提供工件与示例，不附带 Provider 生成的测试结论（passed/report/digest 均不应出现）
