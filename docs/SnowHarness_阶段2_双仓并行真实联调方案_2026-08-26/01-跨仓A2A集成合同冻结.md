# 01 — SnowHarness ↔ HR Assistant 跨仓 A2A 集成合同冻结

这是阶段 2 唯一跨仓共享合同，两边 Claude 不得自行改 wire。

## 1. 协议

```text
A2A protocol: 0.3.0
Transport: JSON-RPC over HTTP
Streaming: SSE
```

不实现A2A 1.x、旧AgentCard fallback、自定义WebSocket、自定义HR REST。

## 2. Agent Card

唯一 discovery：

```text
GET /.well-known/agent-card.json
```

Live Card必须：
```text
protocolVersion="0.3.0"
preferredTransport="JSONRPC"
url=实际JSON-RPC endpoint
capabilities.streaming=true
```

SnowHarness `runtime_endpoint` 与Card `url`规范化后必须一致。禁止SnowHarness自动改端口；静态example不是live authority。

## 3. Start

HR Contract `streaming_transport=true`，正式Start固定 `message/stream`。

Message：

```text
kind="message"
messageId=新UUID
role="user"
parts=[{kind:"text", text:用户自然语言任务}]
metadata=Public Context
```

不得用JSON-RPC扩展参数发送SnowHarness内部ID。

## 4. Public metadata唯一允许

```text
execution_subject
timezone
current_datetime
locale
conversation_summary
attachment_references
```

未知key由HR Provider fail closed。

## 5. execution_subject

固定对象：

```text
execution_subject:
  subject_id: string
  subject_kind: "platform_user" | "platform_service"
```

两个字段都显式。

禁止：
```text
display_name
tenant_id
employee_id
corp_id
email
userIdentityId
```

SnowHarness：
```text
user → platform_user
service → platform_service
```

`subject_id` 是SnowHarness可信Principal的opaque stable subject，HR不能直接当employeeId。

## 6. current_datetime

若SnowHarness有可信当前时间，每次真正发消息时生成ISO 8601，建议带offset。

HR有合法值则优先；没有则用自己的server clock；不得缓存上次调用时间。

## 7. timezone

SnowHarness有Authority才发，否则省略。

HR可用自己的业务默认时区，但不得回写成SnowHarness可信用户时区。

## 8. locale

HR正式只支持 `zh-CN`。

SnowHarness有locale authority时发送；明确发送其他locale时HR返回contract_error。

## 9. conversation_summary

只在SnowHarness已有合法摘要且允许外发时发送，类型固定string。

## 10. attachment_references

固定为 public reference array，每项至少：
```text
reference_id
resource_type
```

可选：
```text
display_name
media_type
```

禁止本地路径、credential、raw unbounded file content。

HR Request必须严格结构化校验，不能只用dict全放行。

## 11. Resume

正式Resume：
```text
message/send
```

Message：
```text
kind=message
new messageId
role=user
parts=[text supplement]
taskId=原taskId
contextId=原contextId
```

如果Start有execution_subject，Resume **必须重发同一subject**。

可用时重发timezone、locale。

`current_datetime` 必须重新计算为Resume当下时间。

默认不重发 conversation_summary / attachment_references，除非本次补充仍明确需要且策略允许。

## 12. Correlation

Resume必须 same taskId + same contextId。变化即失败。

## 13. 跨Turn continuity

同Thread + same AgentRevision + same RuntimeRevision：

```text
RuntimeSessionBinding.externalSessionRef = A2A contextId
```

后续新Turn复用contextId，但新Invocation必须有新taskId。

## 14. Input-required

Provider：
```text
Task status=input-required
```

保留taskId/contextId和追问文本。

SnowHarness：
```text
user_action.requested → waiting_user
```

补充后same task/context resume。

## 15. Cancel

HR Contract：
```text
cancel=false
```

SnowHarness必须：
- Conformance不跑cancel probe；
- effective cancel=false；
- UI无Stop；
- Interrupt拒绝；
- 不发tasks/cancel。

HR Provider如果被外部直接调用tasks/cancel：
- 返回SDK官方unsupported；
- 禁止只把Task标cancelled但业务仍运行。

## 16. Result

HR继续：
```text
Artifact
├ TextPart = answer
└ DataPart = HrAssistantResult
```

DataPart字段：
```text
request_id
status
answer
result_type
data
actions
error_code
retryable
agent_name
agent_version
```

SnowHarness主展示TextPart，DataPart作为结构化结果。

## 17. Terminal mapping

```text
completed → success
input-required → waiting_user
failed → execution.failed
rejected → execution.failed
canceled → execution.cancelled
```

正常SnowHarness→HR路径不应主动cancel。

## 18. Runtime Authentication

阶段2：
```text
none | bearer
```

建议health和well-known card无需bearer，JSON-RPC endpoint在bearer模式要求Authorization。

Runtime credential与execution_subject独立。

## 19. 安全禁止

Wire禁止：
```text
SnowHarness tenantId/threadId/turnId/invocationId/bindingId/routeId/traceId
ContextHandle
GatewayAccessToken
SnowHarness内部WorkloadToken
employeeId
corpId
```

## 20. 合同变更纪律

发现合同不够用时，先改本文件并双边评审，再同时迁移。Claude无权自行扩metadata或状态语义。
