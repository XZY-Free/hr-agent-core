# 00 — 阶段 2 主控与并行编排

## 1. 唯一目标

用真实 HR Agent Provider 证明 SnowHarness 已经成为真正通用的黑盒 Agent Harness，而不是只在仓内 Test Provider 上成立。

结束时必须同时成立：

```text
HR Provider公共A2A合同自洽
+
SnowHarness无HR特例
+
两端只通过冻结公共合同耦合
+
真实进程、真实HTTP/SSE、真实A2A Task完成联调
+
Web/Desktop完成正式自动化验收
```

## 2. 为什么按双仓并行

SnowHarness负责 Contract Snapshot、Revision、Publication、Runtime Registration、Conformance、Route/Binding、Context、Credential、Session、Transport、Event、Web/Desktop。

HR Agent负责顶层 Public Agent Contract、Agent Card、JSON-RPC Provider、ExecutionSubject接收、HR内部 identity mapping、Orchestrator、input-required、Resume、structured result。

因此并行单位固定为 Provider side 与 Consumer side，不按“前端/后端”拆。

## 4. 写入边界

Track H 只写 `hr-agent-core`。

Track S 只写 SnowHarness。

Join 先只读核对两个 Track 的 commit / tests。修复时：
- Provider bug 回 HR 仓；
- Consumer bug 回 SnowHarness；
- 禁止在另一仓绕过。

## 5. 禁止交叉补丁

HR Provider 端口错，禁止 SnowHarness 写 `if hr-assistant then 8100`。

HR metadata解析错，禁止 SnowHarness发HR专属wire。

SnowHarness Resume没重发subject，禁止 HR 从旧task偷偷继承身份。

## 6. 已确认的 Provider 问题

### Endpoint Authority不一致

当前 Agent Card本地默认 `127.0.0.1:8000`，Public A2A Server实际监听 `127.0.0.1:8100`。必须单Authority。

### cancel=false 与 Provider cancel实现矛盾

Public Contract声明 `cancel=false`，但当前A2A Executor仍会把Task标cancelled。必须改成official unsupported语义，不能伪取消。

### Resume身份连续性需要显式冻结

HR Public Runtime每次 invoke 都根据本次 `execution_subject` 计算内部 user_id。Resume如果不带subject会退化anonymous。跨仓合同必须明确每条外部请求的trusted subject。

### registration example会因阶段1新schema过时

当前还是旧 `conformance.start_input/resume_input`，阶段2必须对齐 capability-driven schema。

## 7. 不要把false改成true

HR Contract当前明确：

```text
incremental_content=false
cancel=false
durable_task_recovery=false
```

阶段2不为了“功能多”改成true。没有真实能力就准确false。

## 8. 测试分层

Provider Contract Test：HR仓内证明Card、Contract、Request、A2A lifecycle、Auth、Endpoint。

Consumer Integration Test：SnowHarness仓内证明不读HR源码，只接public contract+endpoint。

Cross-repo True E2E：必须真实HR进程+真实SnowHarness+MySQL+HTTP/SSE+A2A，不能用仓内test provider替代。
