# 10 — 并行分支与合并纪律

## 1. 推荐并行单位

优先：
```text
Claude会话H → 只打开 hr-agent-core
Claude会话S → 只打开 SnowHarness
```

两个会话同时工作。

不建议两个无隔离会话直接改同一repo工作区。

## 2. 若进一步并行HR Track

只有独立git worktree/branch才允许：

```text
H-A endpoint/auth
H-B identity/context
H-C lifecycle/artifacts
```

### H-A Owner
- public_a2a/settings.py
- public_a2a/card.py
- public_a2a/server.py
- auth helper/middleware
- endpoint/auth tests

### H-B Owner
- public_runtime/request.py
- public_runtime/identity_adapter.py
- context/identity tests
- public_subject_ref CLI

### H-C Owner
- public_a2a/executor.py
- public_runtime/runtime.py
- registration generator/artifacts
- lifecycle tests

真实职责迁移时先记录，不能两个lane同时修改同一正式函数。

## 3. HR合并顺序

```text
H-A
→ H-B
→ H-C
→ 全量HR测试
```

冲突时按冻结合同解决，不保留双方旧/新双路径。

## 4. SnowHarness并行

Stage1 COMPLETE后建议单会话完成。

如拆：
- S-A只写scripts/integration + runner tests；
- S-B只写e2e live specs；
- production core bug回单一整合会话修。

## 5. Commit纪律

建议语义commit，不要求逐文件commit。

HR可类似：
```text
fix: 统一公共A2A端点与访问认证
fix: 收口公共执行主体与上下文合同
fix: 对齐A2A续聊取消与注册工件
```

SnowHarness可类似：
```text
test: 增加通用外部智能体真实联调入口
test: 增加Web Desktop live external agent验收
```

字面不强制。

## 6. Push

默认：
```text
commit可以
push不可以
```

除非用户明确要求。

## 7. 禁止

- 两个Claude写同一未隔离工作区；
- 一个Claude同时修改两个repo；
- 复制类减少冲突；
- 冲突时保留legacy/new双路径；
- merge/cherry-pick后不跑全量测试。
