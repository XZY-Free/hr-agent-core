# 01 — HR 智能体契约化改造方案

> 事实基线：`00-HR智能体契约事实基线.md`
>
> 本方案只修改 `hr-agent-core`。
>
> SnowHarness 在本方案中只作为外部黑盒调用方，不依赖 HR Agent 源码、框架或内部拓扑。

---

# 一、改造目标

最终让 SnowHarness 只看到一个：

```text
企业人力智能助手
```

对外链路：

```text
SnowHarness
    ↓
公共智能体合同
    ↓
顶层智能体卡片
    ↓
顶层 A2A Provider
    ↓
HR Orchestrator
    ↓
内部 Leave / Consult / Employee Data
```

内部结构对 SnowHarness 完全不可见。

---

# 二、公共智能体身份

不得继续使用：

```text
root_agent
hr_orchestrator
```

作为平台公共身份。

建议公共稳定标识：

```text
hr-assistant
```

中文展示名：

```text
企业人力智能助手
```

公共版本：

```text
1.0.0
```

注意：

- 公共版本不等于内部任一子智能体版本；
- 内部 Consult / Employee Data 升级，只要公共合同语义未变，可以不强制改变公共 Agent Revision；
- 如果公共能力、上下文合同、协议语义或结果语义发生破坏性变化，必须产生新的公共契约版本。

---

# 三、第一版公共能力清单

能力（Capability，表示智能体擅长处理的任务领域）只用于：

- 展示；
- 搜索；
- 发现；
- 未来智能体自动选择；
- 使用说明。

不得用作函数调用入口。

第一版冻结四个能力域。

## 3.1 假勤与请假服务

稳定键：

```text
leave-and-attendance-service
```

中文名称：

```text
假勤与请假服务
```

包括：

- 请假申请；
- 请假修改相关对话；
- 补登；
- 假期类型理解；
- 日期与时长理解；
- 排班/余额/资格校验后的办理；
- 提交前确认；
- 失败后的继续沟通。

不把：

```text
submit_leave
get_schedule
```

暴露成公共能力。

## 3.2 员工本人信息服务

稳定键：

```text
employee-self-service
```

包括：

- 本人假期余额；
- 本人医疗期；
- 工龄信息；
- 年假折算。

不暴露：

- employee_id；
- Gaia API；
- 内部 Tool 名称。

## 3.3 人力制度与福利咨询

稳定键：

```text
hr-policy-and-benefits-consultation
```

包括：

- 考勤制度；
- 请假制度；
- 入离职；
- 试用期；
- 薪酬；
- 补贴；
- 福利；
- 地区差异类人力政策。

## 3.4 人力系统与文档协助

稳定键：

```text
hr-system-and-document-assistance
```

包括：

- 人力系统操作说明；
- 人力手册；
- 人力文档问答；
- 合法文档引用或附件辅助。

---

# 四、暂不进入公共能力的现有功能

## 4.1 页面跳转

当前：

```text
[[JUMP:xxx]]
```

属于宿主产品协议。

第一版不得把它伪装成通用 A2A 能力。

处理方式：

- HR Agent 内部可以继续使用；
- SnowHarness 调用时，没有统一宿主动作合同就降级成自然语言说明；
- 后续另立“宿主动作合同”后再恢复跨宿主页面动作。

## 4.2 人工转接

当前主要是话术确认，不等于存在通用可验证的转人工系统调用。

第一版能力合同不宣传：

```text
已具备跨宿主真实人工转接
```

除非后续存在正式人工服务动作合同和真实执行证据。

## 4.3 取消请假

当前主要是打开“我的表单”页面引导，不等于 Agent 自己执行取消。

不得把它描述成：

```text
可以直接撤销请假单
```

# 五、顶层智能体卡片

新增顶层智能体卡片（`AgentCard`，A2A 对外公开身份、版本、协议、能力和端点的标准描述）。

建议新增独立模块，例如：

```text
apps/orchestrator/public_a2a/card.py
```

最终公开：

```text
/.well-known/agent-card.json
```

至少包含：

- 公共名称 `hr-assistant`；
- 中文/英文兼容描述；
- 公共版本；
- A2A 协议版本；
- JSON-RPC 传输；
- 输入模式；
- 输出模式；
- 四个公共能力；
- 真实支持的流式能力；
- Provider 信息；
- 公共 Runtime URL。

禁止在卡片中暴露：

- veADK；
- AgentKit；
- root_agent；
- leave_agent；
- Consult URL；
- Employee Data URL；
- Gaia；
- 内部 Prompt；
- Tool；
- API Key。

# 六、增加机器可读公共智能体合同

A2A 智能体卡片本身不足以完整表达：

- 调用上下文合同；
- 流式传输与内容增量的区别；
- 持久恢复能力；
- 结果合同；
- SnowHarness 所需的上下文语义。

因此新增一份通用机器可读合同：

```text
/.well-known/agent-contract.json
```

建议代码位置：

```text
apps/orchestrator/public_contract/
```

至少包含：

```text
contract_version
agent
capabilities
invocation_context
interaction
result_contract
```

必须由代码生成/校验，不允许手工维护一份与运行代码无关系的 JSON。

# 七、HR Agent 调用上下文合同

调用上下文合同（Invocation Context Contract，声明调用整个智能体时平台可以或应该提供哪些通用上下文）不是业务参数表。

严禁：

```text
annual_leave:
  employee_id: required
  year: optional
```

这种 Tool 化设计。

## 7.1 执行主体

上下文种类：

```text
execution_subject
```

中文含义：

> SnowHarness 本次执行所代表的可信调用者身份。

第一版建议：

```text
necessity = preferred
```

而不是全局 `required`。

原因：

- 制度咨询不一定需要身份；
- 本人信息/请假办理需要身份；
- SnowHarness 不应为了决定是否传身份而被迫把自然语言任务先硬分类成某个内部能力。

合同允许增加：

```text
applies_to
```

用于声明它主要服务于：

```text
leave-and-attendance-service
employee-self-service
```

但第一版运行时不能因此建立“按能力函数调用”的第二体系。

有可信身份且策略允许：

```text
尽量提供
```

没有身份：

- 普通制度咨询仍可运行；
- 本人数据或办理业务由 HR Agent 返回稳定身份缺失结果；
- 不允许让用户输入 employee_id 冒充可信身份。

## 7.2 时区

```text
timezone
```

建议：

```text
preferred
```

用于：

- “明天”；
- “后天”；
- “下周三”；
- 跨时区日期理解。

## 7.3 当前时间

```text
current_datetime
```

建议：

```text
preferred
```

当前代码在构建 Orchestrator 时把 `date.today()` 写入 Prompt。

这会使长时间运行进程跨自然日后继续使用旧日期。

本轮必须修正为：

> 当前日期/时间在每次执行时确定，不得在服务启动时冻结。

如果调用方提供可信时间上下文，优先使用合同允许的时间事实。

## 7.4 语言区域

```text
locale
```

建议：

```text
preferred
```

第一版声明：

```text
zh-CN
```

为正式支持语言。

不要继续把：

```text
locale = zh-CN
```

写死成内部调用方身份的一部分。

## 7.5 对话摘要

```text
conversation_summary
```

建议：

```text
preferred
```

只在：

- 当前任务需要前文；
- SnowHarness 有合法摘要；
- 数据策略允许；

时提供。

优先摘要/引用，不默认把整个 Thread 历史全量复制给外部 Agent。

## 7.6 附件引用

```text
attachment_references
```

建议：

```text
accepted
```

主要服务：

```text
hr-system-and-document-assistance
```

不得默认把所有附件发送给 Agent。

只在：

- 当前任务相关；
- Caller 有权访问；
- Agent 合同允许；
- 数据策略允许；

时发送引用。

# 八、公共身份映射

新增公共执行主体适配层。

目标：

```text
SnowHarness ExecutionSubject
→ HR Agent Public Identity Adapter
→ internal trusted user identity
→ existing TrustedIdentityResolver
→ employee_id
```

要求：

1. SnowHarness 不传 `employee_id`；
2. SnowHarness 不传 `corp_id`；
3. 用户自然语言不能创建 trusted subject；
4. HR Agent 自己负责平台主体到员工业务身份的映射；
5. 映射失败使用稳定机器错误，不泄露内部映射表；
6. 结果继续优先输出不可逆 `employee_ref`。

不得让：

```text
A2A user_id
```

在公共合同里等价成：

```text
employee_id
```

---

# 九、顶层公共请求对象

新增公共请求语义对象，例如：

```text
HrAssistantRequest
```

它不是内部 `A2ARequestContext` 的别名。

逻辑上至少包含：

- request id；
- 原始用户任务；
- A2A context id；
- 允许的公共 Context；
- execution subject（如果实际提供）；
- locale/timezone/current datetime；
- conversation summary；
- attachment references。

禁止：

- `caller_agent = hr_orchestrator`；
- employee_id；
- corp_id；
- 内部 runtime key；
- Gaia 凭据。

---

# 十、公共执行门面

必须建立一个唯一公共执行门面，例如：

```text
HrAssistantRuntime
```

职责：

```text
Public Request
→ validate
→ normalize context
→ establish/restore session
→ invoke existing HR Orchestrator business path
→ normalize public result
```

要求：

- AgentKit 服务入口和 A2A Provider 不能复制两套 HR 路由；
- 内部 Leave / Consult / Employee Data 仍按当前职责运行；
- 不允许 A2A Provider 自己再实现一份 `if message contains ...` 路由；
- 不允许通过本机 HTTP 回环调用自己的 `/run_sse` 作为长期架构；
- 应复用同一个应用服务/Runner/业务入口。

如果当前 AgentKit/veADK 暂时没有可直接复用的 Runner API：

> Codex 必须先事实审计，确定最小抽离点，再实施；不得复制 Prompt 或路由逻辑。

---

# 十一、顶层 A2A Provider

新增：

```text
apps/orchestrator/public_a2a/
```

逻辑职责：

- card；
- contract；
- executor；
- server；
- result mapping。

对外：

```text
/.well-known/agent-card.json
/.well-known/agent-contract.json
A2A JSON-RPC endpoint
/health
```

A2A Provider 只负责协议适配。

不负责：

- 业务路由；
- Tool选择；
- 员工身份业务映射；
- Knowledge；
- Leave规则。

---

# 十二、会话与任务

公共 A2A：

```text
contextId
```

对应 HR Agent 连续会话。

公共：

```text
taskId
```

对应本次具体任务。

要求：

```text
同一个 contextId
可以包含多个不同 taskId
```

不能把：

```text
contextId = taskId
```

长期绑定。

SnowHarness 后续使用同一个 Runtime Session 时，可以继续同一 HR Agent 上下文。

---

# 十三、等待用户补充与恢复

等待用户补充（`input-required`，任务缺少真正业务信息时暂停并等待用户继续输入）必须统一支持。

例如：

```text
用户：
帮我请假

HR Agent：
缺少假期类型和日期
→ input-required
```

SnowHarness 再发送用户补充时：

```text
Resume same task/context
```

这里的恢复（Resume，继续原任务而不是创建无关新任务）必须有真实测试。

Leave 现有：

- 槽位收集；
- 一次问清多项缺失；
- 提交前确认；

必须复用，不重写成函数参数表。

---

# 十四、取消

只有满足以下真实测试后，顶层智能体卡片/公共合同才能声明取消支持：

```text
long-running task
→ tasks/cancel
→ active work stops
→ task cancelled
→ no later completed
```

如果底层 veADK/Tool 无法真正停止：

- 第一版公共合同不得宣称强取消；
- 可以声明“取消请求已接收但不能保证底层停止”只作为内部事实；
- SnowHarness 正式 `cancel=true` 能力必须等待真实实现。

---

# 十五、流式能力

公共合同必须区分：

```text
streaming_transport
```

中文含义：

> 支持通过 A2A 流式通道连续接收任务事件。

和：

```text
incremental_content
```

中文含义：

> 支持回答正文自身逐步增量产生。

第一版可以：

```text
streaming_transport = true
incremental_content = false
```

如果顶层真实网络测试证明如此。

不得把 SSE 存在直接描述成“Token流式输出”。

---

# 十六、持久恢复

当前第一版公共合同必须诚实：

```text
durable_task_recovery = false
```

直到：

- TaskStore 持久化；
- 服务重启；
- 重新查到 task；
- resume/cancel 仍有效；

全部真实测试通过。

---

# 十七、顶层统一结果合同

新增统一公共结果对象，例如：

```text
HrAssistantResult
```

建议稳定字段：

```text
request_id
status
answer
result_type
data
actions
error_code
retryable
agent_name
agent_version
```

说明：

- `answer`：人类可读主回答；
- `result_type`：结果类别；
- `data`：可选结构化数据；
- `actions`：可选宿主可执行动作；第一版本若没有通用动作协议则为空；
- `error_code`：稳定机器错误；
- `retryable`：是否适合重试。

不要直接把 Consult / Employee Data 的所有内部字段透传成公共 Schema。

内部结果先进入：

```text
public result mapper
```

再形成稳定公共结果。

---

# 十八、错误语义

至少统一：

```text
identity_required
identity_unverified
input_required
not_found
rejected
temporarily_unavailable
failed
cancelled
contract_error
```

具体代码值可以由实现阶段统一。

必须保证：

- 用户展示文本与机器错误分离；
- 不泄露 SDK、JWT、字段名、内部URL；
- 内部子 Agent 错误不能把 `hr-consult-agent` 等内部拓扑暴露给 SnowHarness。

---

# 十九、内部 A2A 合同保持私有

现有：

```text
A2ARequestContext
RemoteAgentSpec
CONSULT_SPEC
EMPLOYEE_SPEC
```

继续只属于 HR Agent 内部。

公共 A2A Provider 不得把它们直接 export 成外部合同。

后续内部 Consult / Employee Data 可以独立升级，只要公共合同不变。

---

# 二十、契约测试

必须新增一套顶层 Contract Test。

至少覆盖：

## 智能体卡片

- 可发现；
- 名称/版本稳定；
- 协议版本正确；
- 能力唯一；
- 不泄露内部拓扑；
- URL正确；
- Secret为0。

## 公共合同

- Capability不是函数列表；
- Context Contract完整；
- Context Contract来源可审计；
- Digest稳定；
- 破坏性变更产生新版本。

## 身份

- 有可信 subject 的本人数据查询成功；
- 无subject的制度咨询成功；
- 本人数据缺subject返回稳定身份错误；
- 客户端伪造 employee_id 被拒绝；
- Secret/employee_id/corp_id 不进入公共消息。

## 会话

- 两个 Turn 共享 contextId；
- 两个 Task 有不同 taskId；
- 不同用户会话隔离。

## input-required

- 缺业务信息进入 input-required；
- 一次说明多项缺失；
- 恢复同一个 task/context；
- 最终 completed。

## 流式

- 官方客户端走真实网络；
- status/artifact事件顺序正确；
- 不虚报 incremental content。

## Cancel

只有真的做到底层中断才宣称支持。

## 结果

- TextPart 可读；
- DataPart符合公共 Schema；
- 内部子 Agent 名称不泄露；
- 稳定错误码。

# 二十一、SnowHarness 注册产物

HR Agent 改造完成后，仓库必须能够生成一套完全不依赖源码的注册资料：

```text
agent-card.json
agent-contract.json
runtime-registration.example.json
snowharness-registration.md
contract-test-report.json
```

其中：

```text
snowharness-registration.md
```

只告诉平台管理员：

- Agent稳定身份；
- AgentCard URL；
- Contract URL；
- Runtime endpoint；
- protocol/version；
- authentication mode；
- capability摘要；
- Context Contract摘要；
- 已验证交互能力；
- 未支持能力；
- 注册与Conformance步骤。

不得要求 SnowHarness 查看 HR Agent 源码。

# 二十三、完成定义

完成后必须做到：

1. SnowHarness只注册一个“企业人力智能助手”；
2. SnowHarness不知道内部子Agent；
3. SnowHarness不知道veADK/AgentKit；
4. 顶层AgentCard真实可发现；
5. 公共能力不是Tool列表；
6. Context Contract是Agent级合同；
7. 身份不传employee_id；
8. 当前日期不在进程启动时冻结；
9. input-required/resume真实通过；
10. streaming能力不虚报；
11. cancel只有真实实现才声明；
