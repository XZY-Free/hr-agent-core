# WP-06 公共上下文与附件适配整改

## 1. 目标

当前公共请求已经允许：

- timezone
- current_datetime
- locale
- conversation_summary
- attachment_references

前四项已有不同程度消费。

`attachment_references` 目前缺少稳定消费闭环。

本专题目标不是修改 SnowHarness，而是让 hr-agent-core 对当前公共合同做到：

> 能解析就安全解析；不能解析就明确报错；绝不静默忽略。

---

## 2. 当前合同保持不变

`AttachmentReference` 继续只有：

- reference_id
- resource_type
- display_name
- media_type

不得本轮新增：

- local_path
- raw_content
- access_token
- client_secret

---

## 3. 新增 Attachment Resolver 边界

在 Public Runtime 引入单一附件解析职责。

固定建议位置：

```text
apps/orchestrator/public_runtime/attachments.py
```

接口语义：

```text
AttachmentReference
        ↓
AttachmentResolver
        ↓
ResolvedAttachment | ResolutionError
```

不要把 attachment resolution 放进 Prompt。

---

## 4. Resolved Attachment 必须是安全对象

至少：

- canonical reference
- media_type
- display_name
- access_mode
- optional safe http/https URL
- optional already-sanitized text

不得包含：

- 本地任意路径；
- credential；
- raw authorization header；
- file://；
- 用户可控制的内部网络 URL。

---

## 5. 当前没有外部 resolver 时的行为

因为本轮不能修改 SnowHarness，也没有现成 SnowHarness 文件读取连接器，所以**不得伪造解析能力**。

当公共请求包含附件，而运行时没有配置可解析该 `resource_type` 的 resolver：

返回稳定：

```text
attachment_not_resolvable
```

用户文案：

> 当前附件引用暂时无法读取，请提供可访问的文档链接或使用已支持的附件来源。

不得：

- 忽略附件继续回答；
- 假装“已读取”；
- 把 reference_id 当 URL；
- 在模型里让它猜文件内容。

---

## 6. URL 文档能力保持现有路径

如果用户正文已经明确包含安全 `http/https` 文档链接：

- 继续走现有 parse_document；
- 不要求把 URL 强行包装成 attachment reference。

这与公共 attachment reference 是两条不同输入路径。

---

## 7. 已解析附件到 Consult

如果 Resolver 得到：

### 安全文本

使用现有 `DocumentContext` 机制传给 Consult：

- URL / canonical source；
- sanitized content；
- size limit；
- sensitive scan。

### 安全远程 URL

可以让 parse_document 读取，但必须先过：

- scheme 检查；
- host 检查；
- no localhost；
- no credential in URL；
- SSRF guard。

---

## 8. 多附件

本轮固定：

- 一次最多处理 5 个 attachment reference；
- 超过返回 `attachment_limit_exceeded`；
- 每个解析后的文本单份不超过 30k；
- 总上下文不超过 60k；
- 超限不 silently truncate transaction-critical content；
- 对纯咨询文档可明确标记 truncated。

---

## 9. 与 conversation_summary 分离

附件内容不得直接混进：

```text
conversation_summary
```

原因：

- summary 是对话上下文；
- attachment 是外部证据；
- 敏感检查和生命周期不同。

两者必须是不同结构。

---

## 10. Local Root 的消费

Local Root 不是文档解析 Authority。

如果附件问题属于 HR 文档咨询：

- semantic router -> Consult；
- resolved document context -> Consult A2A。

如果用户只上传附件但没有提问：

- `needs_clarification`；
- 不自动总结。

---

## 11. Session 生命周期

Resolved document context 可以在当前 context 的 session state 中保留必要的安全摘要/引用。

不得持久保存：

- credential；
- 原始二进制；
- 不受限全文；
- employee id。

新 task 如果没有再次引用附件，不应自动把整份文档塞给 Consult。

---

## 12. 错误码

至少：

```text
attachment_not_resolvable
attachment_type_not_supported
attachment_invalid
attachment_sensitive
attachment_limit_exceeded
attachment_too_large
```

这些是业务输入/适配错误，不要映射成：

```text
model_failed
```

---

## 13. 测试矩阵

- 无附件 -> 原行为
- 一个支持的引用 -> resolve
- 一个不支持 resource_type -> explicit error
- 5 个 -> allowed
- 6 个 -> limit error
- local path 形态 -> contract error
- file:// -> contract error
- URL credential -> reject
- localhost URL -> reject
- sensitive content -> reject
- 解析后 Consult 能读取
- 解析失败时模型不得被调用去“猜”
- 只上传附件不问问题 -> clarification
- 新 task 不自动继承全文

---

---

## 15. WP-06 完成门禁

必须满足：

1. attachment reference 不再静默忽略；
2. 无 resolver 时明确失败；
3. 不修改 SnowHarness；
4. 不引入 local path；
5. 不引入 raw credential；
6. Consult 文档上下文可验证；
7. SSRF / sensitive tests 通过。
