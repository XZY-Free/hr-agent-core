## 1. 执行原则

实施 AI 必须严格按此表推进。

不允许：

- “先把容易的做了”；
- 一次横跨所有 WP 大改；
- 先改 Prompt 再补领域规则；
- 一边整改一边重写全部架构。

1. 记录当前 commit；

4. 不修改代码。

输出基线信息即可，不要先修 unrelated failure。

## 11. 每个 Phase 的最小交付

每个 Phase 完成后必须：

1. 按当前 AgentKit 远端验收口径运行该 WP 对应用例（`tests/agentkit`），不在本地装配业务 Agent；
2. 运行可执行的回归集合（以 `tests/agentkit` 为当前入口，旧 `/tests/eval` 仅历史记录）；
3. `git diff --check`；
4. 搜索敏感字段泄露；
5. 输出变更文件列表；
6. 输出未完成项；
7. 未完成项非空时，不得写“完成”。

除非上层用户另有明确要求：

- 不 push；

- 不写云端配置；

## 14. 最终变更完成后必须执行

按当前口径，默认验收入口是 `tests/agentkit` 远端客户端：

