# WP-03 Employee Data 本人数据能力恢复整改

## 1. 目标

保持 Employee Data Agent 的正确安全边界：

- 只读；
- 只查当前员工本人；
- 不接受用户指定 employee_id；
- 不解释制度；
- 不办理请假；
- 数字来自确定性 Provider。

同时恢复旧系统已经具备、拆 Agent 时丢掉的本人数据能力。

---

## 2. 当前问题

当前独立 Employee Data 实际只公开两个模型工具：

- `calc_annual_leave`
- `get_medical_period`

Provider 也只定义：

- `annual_profile`
- `medical_period`

Runtime 的 `leave_balance` 最终又固定选择：

```text
年休假
```

因此：

> “我的假期余额”

被压成：

> “您的年休假余额……”

而：

> “我还有几天育儿假？”

又可能因为 `_POLICY` 里直接包含“育儿假”而被当制度问题拒绝。

这属于能力缩水，不是智能体化的必要结果。

---

## 3. 目标能力边界

Employee Data 最终负责：

### 本人全部假期余额

例如：

- 我的假期余额；
- 我还有哪些假；
- 所有假期余额。

### 指定本人假种余额

例如：

- 我的年休假还剩多少；
- 我的育儿假还有几天；
- 我的调休还有多少；
- 我的病假余额；
- 我的全薪病假还剩多少。

### 医疗期

- 医疗期额度；
- 已用；
- 剩余。

### 工龄 / 参工信息

### 年休假档位与折算

不负责：

- 上海育儿假政策；
- 育儿假怎么申请；
- 病假需要什么材料；
- 迟到扣款制度；
- 办请假；
- 查询其他员工。

---

## 4. Provider 接口必须扩展

共享 Employee Data Provider 必须具备：

```text
leave_balances(employee_id)
annual_profile(employee_id)
medical_period(employee_id)
```

其中：

`leave_balances` 是**第一类能力**，不能再依附在 annual_profile 里。

---

## 5. 假期余额数据不能继续丢字段

当前 `packages/hr_domain/gaia/leave_query.py` 只保留：

- leave_name
- effective_year
- total
- used
- remain

旧 Gaia 数据还具有：

- leaveCode
- leaveUnit
- leaveApproving / freeze

整改后的 normalized balance row 至少保留：

- leave_code
- leave_name
- effective_year
- unit
- total
- used
- remain
- approving / freeze

### 5.1 unit

必须明确：

```text
day
hour
```

不能只留数字。

原因：

- Leave WP-02 需要按同单位比较余额；
- Employee Data 对用户也必须说明“天”还是“小时”。

### 5.2 freeze / approving

用户问“为什么余额和可用额度不一样”时，这是重要本人事实。

即使第一版回答不展示，DTO 也不能在 Provider 层丢失。

---

## 6. 年休假特殊处理

旧系统对年休假可能按 effective year 聚合/展示。

整改要求：

- 年休假余额仍允许返回多个 effective year 条目；
- 不要为了“简化回答”在 Provider 层只取第一行；
- Runtime renderer 可以按年份说明；
- 原始 normalized list 保存在结果 data。

---

## 7. Query Type 重新定义

最终至少支持：

```text
leave_balance_all
leave_balance_by_type
medical_period
employment_info
annual_leave_calculation
```

### 7.1 `leave_balance_all`

触发语义：

- 我的假期余额；
- 我还有哪些假；
- 我所有假还剩多少。

### 7.2 `leave_balance_by_type`

携带：

```text
target_leave_type
```

例如：

- 育儿假
- 年休假
- 调休假
- 病假

target type 必须经过共享假种标准化。

---

## 8. 育儿假路由必须按“问题意图”，不能按词

删除当前这种语义：

```text
出现“育儿假” -> policy reject
```

必须区分：

### Employee Data

> 我还有几天育儿假？

### Consult

> 四川育儿假有几天？

> 育儿假怎么申请？

> 育儿假需要什么材料？

---

## 9. Employee Data Agent Prompt

Prompt 只负责：

- 判断调用哪个只读工具；
- 不修改数字；
- 不解释制度；
- 不查询别人。

删除/改掉：

> 只处理年假余额……

改成：

> 只处理当前员工本人各种假期余额、医疗期、工龄、年休假折算。

---

## 10. 数字输出继续由 Runtime 确定性渲染

这是现有设计的优点，必须保留。

不要变成：

```text
工具返回 data -> LLM 自由组织数字
```

成功结果的关键数字必须由 deterministic renderer 生成 `answer`。

模型可用于工具选择，但最终机器事实不能被改写。

### 10.1 指定假种示例

输入：

> “我的育儿假还剩多少？”

Provider：

```text
leave_name=育儿假
remain=5
unit=day
```

Runtime：

> 您的育儿假余额为 5 天。

### 10.2 全部假期

按稳定顺序展示：

- 假种；
- 剩余；
- 单位；
- 必要时 effective year。

不要在一段模型文案里随机排序。

---

## 11. 无匹配假种

如果 Gaia 返回了余额列表，但目标假种没有记录：

状态应明确为：

```text
not_found
```

错误码固定：

```text
leave_balance_not_found
```

不得：

- 取列表第一项冒充；
- 返回 0；
- 自动查年休假。

---

## 12. 安全边界

以下保持不变：

- 跨员工查询拒绝；
- identity_unverified fail closed；
- employee_ref 可以返回；
- employee_id 不进入结果；
- 用户不能通过文本切换 employee；
- model 不能调用任意员工查询。

跨员工安全最终由 Employee Data Runtime 负责，不以 Orchestrator Router 的关键词判断作为唯一保护。

---

## 13. A2A 合同

扩展 Employee Data A2A 结果的 `query_type` 枚举与 data shape。

Orchestrator `EMPLOYEE_SPEC` / `_validate_employee_numbers` 同步调整。

要求：

- 新 query type 都有显式验证；
- `leave_balance_by_type` 校验 answer 中包含 remain + 单位；
- `leave_balance_all` 校验 data rows 合法；
- 不因为 contract 扩展降低数字一致性校验；
- data 中不得包含 employee_id。

---

## 14. 与 Consult 的职责去重

当前 `apps/consult_agent/prompts.py` 还写着：

- get_leave_balance
- get_medical_period
- calc_annual_leave

但 Consult Agent 实际并没有这些工具，Runtime 又会拒绝个人数据。

WP-03 要同步清理这段 Prompt。

最终：

### Consult

> 本人数据 -> 明确不是自己的职责。

### Employee Data

> 本人数据 -> 唯一 Authority。

不得两个 Agent 都宣称自己能查本人数据。

## 16. 测试矩阵

### 指定余额

- 年休假
- 育儿假
- 调休假
- 病假
- 全薪病假
- 小时制假
- 不存在假种

### 全部余额

- 多假种；
- 年休假多个年份；
- 天 + 小时混合；
- freeze；
- 空列表。

### 语义区别

- “我还有几天育儿假？” -> Employee Data
- “四川育儿假几天？” -> Consult
- “育儿假怎么申请？” -> Consult
- “我的育儿假怎么申请？” -> Consult（问流程，不是余额）
- “我的假期余额” -> Employee Data
- “假期余额制度怎么规定？” -> Consult

### 安全

- 查同事育儿假 -> reject
- 指定工号 -> reject
- identity unverified -> reject
- Gaia unavailable -> retryable unavailable
- 不泄露 employee_id

### 数字

- answer 数字必须来自 data；
- hour unit 必须输出小时；
- day unit 必须输出天；
- 不得把 8 小时自动写成 1 天。

---

## 17. WP-03 完成门禁

必须满足：

1. `leave_balances` 是正式 Provider 能力；
2. 不再把“假期余额”默认成“年休假”；
3. 育儿假本人余额可查；
4. 小时/天单位保留；
5. Employee Data / Consult 职责不冲突；
6. A2A contract 通过；
7. 现有年假折算/医疗期能力无回归；
8. 跨员工与身份安全测试无回归。
