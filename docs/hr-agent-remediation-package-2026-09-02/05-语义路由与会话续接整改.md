# WP-05 语义路由与会话续接整改

## 1. 目标

保留现有 A2A 拆分：

- Consult 远程 A2A；
- Employee Data 远程 A2A；
- Leave 本地。

但把当前：

```text
自然语言
 -> 大量 regex
 -> default Consult
```

改成：

```text
continuation / safety deterministic guard
        ↓
structured semantic route decision
        ↓
local / Consult A2A / Employee Data A2A
```

这不是把路由交给“自由发挥的 Agent”，而是使用受限枚举输出的语义路由器。

---

## 2. 当前问题

`apps/orchestrator/a2a/routing.py`

当前正则：

- `_LEAVE_ACTION`
- `_LEAVE_CONTINUATION`
- `_CANCEL`
- `_EMPLOYEE_DATA`
- `_CROSS_EMPLOYEE_DATA`
- `_PAGE`
- `_HANDOFF`
- `_GREETING`
- `_PROVINCE_ONLY`

并且未命中默认：

```text
CONSULT
```

这会导致：

- 业务同义表达靠不停补正则；
- 新增假种/问法导致错路由；
- 多轮补充只有“确认/是的/改成后天”等少数词能被固定识别；
- `育儿假`等语义被多处正则重复判断；
- Router 重新变成工作流意图树。

---

## 3. 本轮不动的路由项

因属于“假实现”后续专题，本轮不要改它们的业务行为：

- page jump 明确指令；
- handoff 明确指令；
- cancel / 撤回的业务动作处理。

如果为了重构 `routing.py` 必须搬代码，只允许**原样保持这些路由语义**。

---

## 4. Deterministic Guard 只保留三类职责

### 4.1 Task continuation owner

最高优先级。

如果 `(context_id, task_id)` 已处于：

- Leave input_required；
- Consult need_more_information；
- Employee Data 后续明确允许的补充状态；

补充消息必须回到原 owner。

不重新做自然语言分类。

### 4.2 协议/安全约束

例如：

- 无效公共合同；
- 敏感字段；
- target Agent 自己的跨员工拒绝。

注意：

跨员工是否允许是 Employee Data 的安全规则，不需要 Router 用复杂文本正则当最终 Authority。

### 4.3 本轮明确排除的现有精确控制命令

page/handoff/cancel 保持现状。

---

## 5. 新增 Structured Semantic Router

新增单一语义路由组件。

固定位置：

```text
apps/orchestrator/a2a/semantic_router.py
```

它只做分类，不访问：

- Gaia；
- Knowledge；
- employee data；
- session secrets；
- 业务工具。

模型配置使用现有 `root` 路由可用的模型配置，不新增另一组未经管理的 API Key。

---

## 6. Route Decision 固定 Schema

输出必须是严格枚举。

至少：

```text
intent:
  leave_transaction
  employee_self_data
  hr_consultation
  attendance_calculation
  general_local
  needs_clarification

target:
  local
  employee_data
  consult

confidence:
  high
  medium
  low
```

可附稳定 `reason_code`，但不能输出自由执行计划。

模型不得返回：

- URL；
- 任意 Agent 名；
- 工具名；
- employee id。

---

## 7. 固定 target 映射

```text
leave_transaction      -> local
employee_self_data     -> employee_data
hr_consultation        -> consult
attendance_calculation -> consult
general_local          -> local
needs_clarification    -> local
```

不得让模型自由决定 target 字符串。

---

## 8. 意图定义

### 8.1 `leave_transaction`

包含：

- 新建请假；
- 补登；
- 修改正在办理的请假；
- 修改类型；
- 修改日期；
- 修改时间；
- 修改理由；
- 对 Leave input_required 的补充。

示例：

- 我想休年假
- 明天不来了，帮我办一天年假
- 帮我把之前那个假改到后天
- 结束时间改成下午4点
- 理由改成复诊
- 年假改病假

### 8.2 `employee_self_data`

只指当前员工自己的可查询事实：

- 假期余额；
- 医疗期；
- 工龄；
- 参工；
- 年假折算。

示例：

- 我的育儿假还有多少
- 我还有哪些假期额度
- 我工龄多久
- 我的年假今年怎么算

### 8.3 `hr_consultation`

- 制度；
- 政策；
- 系统操作；
- 薪酬福利；
- 地区育儿假政策；
- HR 文档。

### 8.4 `attendance_calculation`

- 明确要求迟到/早退金额或旷工量化计算。

### 8.5 `needs_clarification`

当前表达无法可靠判断：

- 是想办假还是问制度；
- 是本人数据还是政策。

低置信度不得默认 Consult。

---

## 9. Low Confidence 策略

当前未命中 regex 默认 Consult 的行为必须删除。

新的规则：

```text
low confidence -> local
```

Local Root 用一句自然追问澄清。

不得：

```text
不知道 -> Consult
```

原因：

Consult 是具体业务域，不是“所有未知问题”的垃圾桶。

---

## 10. Continuation ownership

建立统一的 owner state：

```text
(context_id, task_id) -> owner
```

owner：

- local_leave
- consult
- employee_data

### 10.1 什么时候写入

#### Leave

LeaveDraft status = collecting / input_required 时。

#### Consult

Remote status = need_more_information 时。

#### Employee Data

只有未来确实出现可恢复补充场景才写；目前大部分结果是 terminal。

### 10.2 什么时候清除

- completed
- rejected
- failed
- cancelled
- local runtime exception

### 10.3 不能跨 task 劫持

同一 context：

- task A 正在补 Leave；
- task B 新问制度；

task B 必须独立分类。

---

## 11. 删除 `_looks_like_missing_info` 作为状态 Authority

当前 Public Runtime 根据：

- 是否有问号；
- 是否出现“假期类型/日期/事由”等词；

猜 `input_required`。

整改后：

### Local Runner 返回结构化 Turn Outcome

至少：

```text
status:
  completed
  input_required
  failed

owner:
  local_leave / root

missing_fields: []
```

Public Runtime 直接映射。

### 11.1 模型自然语言只是 answer

例如：

> “请补充日期。”

answer 不能反向决定 status。

---

## 12. Root Prompt 同步清理

当前 Root Prompt 声称：

> “查询假期余额/医疗期/年假天数 → 调用对应查询工具”

但 root 实际没有这些本地工具。

整改后 Prompt 必须与真实架构一致。

如果 ordinary `employee_self_data` 已由 semantic router 直接 A2A，不需要 Root 再声称自己本地调用不存在的工具。

Root 保持：

- Leave 本地分发；
- generic local conversation；
- 本轮未整改的 existing action behavior。

---

## 13. Remote Router 保留的优点

`apps/orchestrator/a2a/router.py` 当前有以下好资产：

- A2A contract 校验；
- agent_name/version 校验；
- remote status 校验；
- Employee Data 数字一致性校验；
- 敏感数据检测；
- 失败不 silent fallback。

这些都保留。

本专题只替换**业务语义选择层**。

---

## 14. 不能做的“简化”

不得：

- 删除 A2A contract；
- 所有消息都先调用三个 Agent 再让 LLM 投票；
- 用 embedding nearest keyword 替代 structured classifier；
- 把 default 改成 Employee Data；
- 新增 100 个 regex；
- 把 active conversation 只存成一句文本标签；
- continuation 仍靠“确认/是的”关键字；
- semantic router 失败时默认 Consult。

Semantic router 自身异常时：

```text
local / needs_clarification
```

不得 silent remote dispatch。

---

## 15. Semantic Router 测试集

至少覆盖每类 20 个自然表达变体。

### Leave 变体示例

- 我想休年假
- 帮我请个假
- 明天想调休
- 后天下午不在
- 我要补登昨天病假
- 上一个假改成后天
- 时间不对，改成16点
- 原因换成复诊
- 年假改病假

### Employee Data

- 我年假还有多少
- 我的育儿假剩几天
- 我有哪些假没休
- 查下本人调休余额
- 我工龄几年
- 今年年休假折算多少

### Consult

- 年假能跨年吗
- 育儿假怎么申请
- 四川育儿假几天
- 病假需要证明吗
- HR系统怎么补卡

### Attendance

- 迟到17分钟扣多少
- 早退65分钟算什么
- 第三次迟到8分钟多少钱

### Ambiguous

- 年假
- 育儿假
- 迟到
- 调休

应：

```text
needs_clarification
```

或结合明确 active owner 继续原任务。

不能随机默认 Consult。

## 16. 多轮路由测试

### Leave

1. “我想请假” -> local Leave input_required
2. “年休假” -> 必须仍 local
3. “明天下午” -> 必须仍 local
4. “改成病假” -> local

### Consult 地区追问

1. “育儿假政策有几天？” -> Consult need_more_information
2. “四川” -> 必须回 Consult，不得被 local/province regex决定

### 同 context 多 task

- task1 Leave pending
- task2 “公司年假制度是什么”
- task2 -> Consult
- task1 补充 -> Leave

## 18. WP-05 完成门禁

必须满足：

1. ordinary business intent 不再由关键词 regex 决定；
2. semantic result 是严格 enum；
3. no-match 不再 default Consult；
4. low confidence -> local clarification；
5. continuation owner 优先于重新分类；
6. local input_required 是结构化状态；
7. Consult province follow-up 不依赖 `_PROVINCE_ONLY`；
8. Employee Data / Consult / Leave paraphrase 路由集通过；
9. existing A2A contract/数字校验不被削弱；
10. 本轮 fake action 路由行为保持原状。
