# WP-07 生产拓扑测试与业务验收整改

## 1. 目标

把“测试绿”从：

> 单模块/兼容拓扑没有报错

升级为：

> 真实生产拓扑能够承接 FastGPT 业务语义，并且 Agent 化后的实现没有丢核心能力。

---

## 2. 当前测试问题

### 2.1 `tests/eval/local_agent.py`

它重新把多个能力塞回单个 root，用来跑旧 21 条基线。

所以 21/21 只能证明：

> 单进程兼容 Agent 能处理这些 case。

不能证明：

- A2A router 正确；
- Employee Data remote 正确；
- Consult remote 正确；
- Public ExecutionSubject -> Leave identity 正确；
- Local continuation 正确；
- production contract 正确。

### 2.2 顶层 A2A protocol test

`test_hr_assistant_a2a_protocol.py` 主要用 RecordingRuntime。

这对 A2A 协议测试是正确的。

但它不能承担业务迁移验收。

所以：

**保留，不删除；重新明确标记为 protocol-only。**

---

## 3. 测试分层

最终形成五层门禁。

### L1 Domain Unit

完全不跑模型。

覆盖：

- leave rules；
- duration；
- schedule tri-state；
- type normalization；
- annual leave；
- attendance calculation；
- balance normalization。

### L2 Agent Contract Unit

用 fake model / fake provider 验证：

- Agent 工具列表；
- runtime status；
- A2A contract；
- structured input_required；
- 数字一致性。

### L3 Integration

真实业务组件组合，但使用 deterministic stub：

- Orchestrator + semantic router；
- Leave + shared identity + Gaia Stub；
- Employee Data A2A；
- Consult + calculation / KB Stub。

### L4 Production-topology E2E

拓扑必须与生产一致：

```text
Public A2A
   ↓
HrAssistantRuntime
   ↓
Semantic Router
   ├── Local Root -> Leave
   ├── A2A -> Consult
   └── A2A -> Employee Data
```

允许：

- Gaia Stub；
- KB Stub；
- model stub / deterministic semantic-router fixture。

不允许：

- 用 monolithic `local_agent.py` 替代拓扑；
- 在 test 里重写业务规则。

### L5 Opt-in Real Integration

不在普通 CI 强制：

- real model；
- real Viking Knowledge；
- real Gaia read-only。

但发布到开发 Runtime 前必须跑。

---

## 4. Golden Case 的来源

Golden Case 不以旧 FastGPT “节点路径”作为目标。

只以旧系统已经确认的**业务语义**作为目标。

不要求：

- 同样的节点数量；
- 同样的 LLM 次数；
- 同样的快捷分流；
- 同样的话术。

要求：

- 业务事实一致；
- 新架构更可靠；
- 旧工作流明显的技术 bug 不复制。

---

## 8. Routing Golden Matrix

每个语义至少 20 个 paraphrase。

关键必须有：

```text
“我想休年假”
“我年假还有多少”
“年假能跨年吗”
```

这三句话分别必须：

```text
Leave
Employee Data
Consult
```

另外必须覆盖：

```text
“迟到17分钟扣多少” -> Consult attendance_calculation
“育儿假” -> needs_clarification（无上下文时）
“四川” -> 若原 task 为 childcare policy continuation，继续 Consult
```

## 15. 覆盖率不是唯一指标

本项目真正门禁是：

```text

```

尤其：

- identity
- leave authoritative duration
- rest-day mode
- schedule unknown
- employee balance
- attendance boundaries
- continuation

这几类任何一例失败，禁止以“整体通过率98%”放行。

## 16. 测试数据原则

Stub 数据必须：

- 能表达休息日/工作日/unknown；
- 能表达夜班；
- 能表达小时余额；
- 能表达多 effective year；
- 能表达 permission/gender；
- 不只覆盖 08:00-17:00 白班 happy path。

不要用一个万能 fixture 把所有场景都变成同样排班。

---

## 17. 禁止通过方式

不得：

- `pytest.skip` 新失败场景；
- `xfail` Critical case；
- 修改 expected 迎合当前错误；
- 单独 mock 掉 semantic router 后宣称路由已验收；
- mock 掉 identity resolver 后宣称 Public Leave 已验收；
- 使用 test-only 业务规则；
- 测试代码直接把 employeeId 塞进 Leave session state。
