# WP-07 生产拓扑测试与业务验收整改

> **当前执行口径（2026-09-05 更新，优先于本节旧口径）**
> 原 L1-L5 本地 stub 验收层已被用户覆盖：测试验收环境切换为 **AgentKit 远端 HTTP 客户端验收**（默认 `testpaths=["tests/agentkit"]`），不再以「电脑本地三服务 + localhost」作为验收层。
> **Gaia 是唯一显式假数据例外（授权 stub 边界）**：`GAIA_BACKEND=stub`、`EMPLOYEE_DATA_BACKEND=stub`、`GAIA_DRY_RUN=true`；真实 Gaia 连通性不计为已通过，也不再索取 Gaia 凭据。
> 已在授权边界内**完成全部 WP 验收**：全量 `tests/agentkit` 远端用例 258 passed / 0 failed / 0 skipped（耗时 925.86 秒），JUnit 证据 `tests/e2e/logs/agentkit-remediation-final-v33-v14-v11-2026-09-05.xml`；WP07（生产拓扑与公共 Cancel 不支持契约）已由最终全量套件覆盖，整体结论 **业务迁移非假实现整改：PASS（AgentKit 开发环境；Gaia 为授权 stub 边界）**。不得以 health 200 / 旧入口冒充完整业务验收通过。
> 下文业务矩阵（Golden Matrix）与失败注入原则不变；只把「测试分层」与「WP-07 完成门禁」的口径更新为云部署服务验收。

## 1. 目标

把“测试绿”从：

> 单模块/兼容拓扑没有报错

升级为：

> 真实生产拓扑能够承接 FastGPT 业务语义，并且 Agent 化后的实现没有丢核心能力。

## 3. 测试分层（当前执行口径，替代旧 L1-L5 本地 stub 分层）

旧「L1 Domain Unit … L5 Opt-in Real Integration」本地 stub 装配分层已被用户覆盖，不再作为验收层保留。

当前实际执行：

- 唯一可执行的验收入口为 **AgentKit 远端 HTTP 客户端验收**（`tests/agentkit`，见 [`docs/agentkit-acceptance.md`](../../docs/agentkit-acceptance.md)）；不在电脑本地拉起三服务，也不再以 fake model / fake provider / deterministic KB-stub 作为验收手段。
- 生产拓扑（`Public A2A → HrAssistantRuntime → Semantic Router → {Leave, A2A Consult, A2A Employee Data}`）通过**对已部署云 Runtime** 的远端客户端用例验证，不重新装配本地业务组件。
- **Gaia 是唯一显式假数据例外（授权 stub 边界）**：`GAIA_BACKEND=stub`、`EMPLOYEE_DATA_BACKEND=stub`；真实 Gaia 接入与 OAuth 缓存未验证、不计为已通过。
- stub 仅在服务端授权范围内使用（Gaia 为授权 exception）；测试不能注入 session state 伪造业务事实。
- 下文 Golden Matrix（§5–§8）与失败注入（§10）的业务目标、具体错误断言不变，不删 case、不改业务口径。

## 4. Golden Case 的来源

Golden Case 不以旧 FastGPT “节点路径”作为目标。

只以旧系统已经确认的**业务语义**作为目标。

不要求：

- 同样的节点数量；
- 同样的 LLM 次数；
- 同样的快捷分流；
- 同样的话术。

要求：

- 业务事实一致；
- 新架构更可靠；
- 旧工作流明显的技术 bug 不复制。

## 16. 测试数据原则

Stub 数据必须：

- 能表达休息日/工作日/unknown；
- 能表达夜班；
- 能表达小时余额；
- 能表达多 effective year；
- 能表达 permission/gender；
- 不只覆盖 08:00-17:00 白班 happy path。

不要用一个万能 fixture 把所有场景都变成同样排班。

## 17. 禁止通过方式

不得：

- `pytest.skip` 新失败场景；
- `xfail` Critical case；
- 修改 expected 迎合当前错误；
- 单独 mock 掉 semantic router 后宣称路由已验收；
- mock 掉 identity resolver 后宣称 Public Leave 已验收；
- 使用 test-only 业务规则；
- 测试代码直接把 employeeId 塞进 Leave session state。
